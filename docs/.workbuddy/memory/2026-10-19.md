## 导入字段映射配置修复与完善（imports）

用户要求修正导入页面字段映射、补全非必填字段、确定必填字段。改动落在 `src/modules/imports/service.ts` + `public/assets/views/import.js` + 路由 schema + 测试。

- **根因**：映射错乱源于字段名语义对调——「类型」列被塞进名为 `recordTypeColumn` 的槽，真正的「方向/收-支」列被标成不读取。改为两字段各归其位：`recordTypeColumn`（6 种记录类型）与 `directionColumn`（支付宝/微信收-支兜底，parseRows 中作为 recordTypeColumn 之后的第二优先级）。
- **新增可选列入契约**：`timeColumn / nameColumn / categoryColumn / counterpartyColumn / feeColumn / discountColumn / tagsColumn` 全部进入 `IMPORT_COLUMN_FIELDS`（唯一出口）、`Mapping`、guessMapping 猜测、parseRows 解析、commit 落库。前端 `MAPPING_FIELDS` 与后端逐项一致，不再三处各写一份。
- **17 列 `doc` 契约**：每列都标 `kind / values / required / consume / hint / defaultValue`（新增 defaultValue 字段）。「实际值/方向/账户/转入账户/记账人」明确标 `consume:null` 并说明为何不读。
- **commit 关键修复**：
  - 新增 `resolveCategoryByName`（「父 › 子」→ 分类 id，闭环导出→导入）与 `resolveTagNames`（标签名 → id）。此前漏了标签名→id 转换，整行报「标签不存在」建不了账。
  - 手续费/折扣按 `FEE_APPLICABLE`/`DISCOUNT_APPLICABLE`（已导出复用，与前端 `lib/amounts.js` 同构，parity 1066 用例通过）判定是否带入。
  - 改进 commit 的 catch：把后端真实校验字段（如 `tags`/`categoryId`）带回界面，不再模糊成「请求参数校验失败」。
- **必填判定**：`dateColumn`+`amountColumn` 必填（缺一项无法建账）；`defaultAccountId` 在 commit 阶段必填（导入统一写入选定账户）。其余 12 列可选，留空均有兜底（已写进 doc 与界面「留空时」列）。
- **验证**：tsc 通过；78 单元/契约测试全过；syntax/template/imports/nav/routes/schema/contrast/url/parity 闸门全过；新增 `scripts/smoke-import-runtime.mjs`（:memory: DB + 迁移跑 commit）端到端验证 手续费/折扣/标签/分类/对象/名称/时间/备注 全部落库正确，转账行被识别为「暂不支持批量导入」。
- 注意：分类树强制费用/收入只能用 level-2 子类别，故 `defaultCategoryId`/`incomeCategoryId` 必须选子类别（前端下拉本就只给子类别）。
